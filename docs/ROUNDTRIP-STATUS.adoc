== IDApTIK: executed and gated (record from 2026-07-27)

`just roundtrip-idaptik` runs end to end. It compiles
`profiles/idaptik/v1/ghost-lobby.ums.json` through the public
`ums-profile-sdk` CLI and its descriptor-gated `packageCompiler` service. The
resolved internal `ums-profiles` implementation consumes the game-owned
`contracts/idaptik/v1` artifacts by path and hands the exact
temporary artifact to IDApTIK's production loader
(`idaptik-core --example package-runner`). The game accepts it, executes a
grounded camera uplink, snapshots, restores into a fresh simulation, replays
the tail, and the recipe fails unless events and final state match.

The `jq` gate asserts the package format, scenario id, seed, `replay_equal`,
`package_guarantees_met`, the snapshot format, the presence of `CameraPinged`,
and six distinct cognitive-trace stages.

Observed 2026-07-27:

....
compiled /tmp/tmp.*.idaptik-package.json
roundtrip-idaptik: UMS artifact accepted, executed, snapshotted, restored
                   and replayed identically
....

This retires a claim that was advertised and unreachable. The recipe and its
internal `ums-profiles` implementation existed on no `main` branch in either
UMS repository until the consolidation in ADR-0015. Since 2026-08-29, the CLI
exercises that compiler only through `ums-profile-sdk`; the implementation
crate is non-publishable.

`rust-ci.yml` now runs the same sequence as a release-blocking step, checking
IDApTIK out as a sibling and building the game's own crate from it. The exact
raw-cargo sequence CI uses (not merely the `just` recipe) was verified locally
on 2026-07-27.

**Observed green in CI on 2026-07-27**, run `30288163489`, step
"UMS to IDApTIK round trip through the real game loader". The gate is real: it
checks the game out as a sibling, builds the game's own crate, and fails the
build if the loader rejects the artifact or the replay diverges.

**Status (2026-07-28; re-run locally 2026-11-15, see the note above): tested.** Every clause of ADR-0014 was then met -- an authored fixture
is validated, compiled, loaded by the real game loader, and compared with the
post-edit model, including deterministic repeat output.

*Deterministic repeat output* -- met. The source is compiled twice and the
artifacts must be byte-identical.

*Compared with the post-edit model* -- met, 2026-07-28. `RoundTripResult` now
carries `accepted`: the loader's own parsed view of the fields a UMS author
writes (`scenario_id`, `seed`, `run_ticks`, `snapshot_tick`, `taxonomy`,
`actors`, `commands`, `guarantees`).
`scripts/compare-authored-vs-accepted.sh` diffs it against the source and fails
the gate on any difference.

It deliberately does **not** compare `scenario`. The compiler copies the
game-owned fixture into the package verbatim, so diffing that back would prove
only that serde round-trips JSON -- a tautology dressed as a contract test.

Verified to fail, not merely to pass: dropping a taxonomy term, retiming a
command, and running against a game too old to export `accepted` each break the
gate.

== Slavia: validated, no loader

`just slavia-profile-check` validates `profiles/slavia/v1/profile.json` and its
Border Path fixture through the generic declarative profile protocol, and an
isolation test prevents Slavia vocabulary reaching UMS core. There is no Slavia
compiler, loader or runtime adapter, and none is claimed. Slavia's own
repository agrees.

== What is still not proved

* Slavia has no loader round trip of any kind.
* The Enaction preview (ADR-0019) ran against the real runner and validator
  by hand on 2026-11-15 (`tests/real_chain.rs`, 5 of 5 passed), but it is not
  in CI. It is not a substitute for a loader round trip.
* The IDApTIK loader round trip passed locally on 2026-11-15; the CI step at
  IDApTIK `58d6936` is OPEN until a run is observed.
